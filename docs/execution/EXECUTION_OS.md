# Bunova Execution OS

`TODO.md` is the sole mutable backlog/status authority. No report, State snapshot, host checklist, issue, audit file or projection may own task state.

Bunova preserves its native Markdown TODO through the hash-bound projection generated by `scripts/executionkit/project-tasks.mjs`. The projection supplies machine-readable lifecycle/dependency/routing metadata only. If its source hash differs from the current TODO/archive, it is stale and must be regenerated.

Execution is sequential: resolve live repository truth, select one earliest dependency-ready lifecycle action, read its native authorities, change only the necessary scope, run targeted verification, reconcile task state/evidence, checkpoint State OS and resolve again. A host `/goal` or similar persistence mechanism keeps the session alive but never selects work.

P00 is accepted historical planning. K00 is mandatory adoption. `K00-019` is the integration audit and `K00-GATE` is activation. P01+ remains blocked behind activation. Each product phase has an independent audit and gate. Full expensive CI is phase-boundary by default; task-targeted checks happen inside tasks.

Blocked work stays visible. Findings become canonical TODO work before remediation. Never mark planned future scope as a defect merely because it is not implemented yet.
